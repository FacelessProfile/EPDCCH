### PDCCH простыми словами
Чтобы трубка поняла, где именно в эфире лежат её данные, базовая станция каждый субкадр(1 мс) отправляет ей короткую инструкцию, она же **DCI** (Downlink Control Information, занимает около 27 бит)

1. **Где передаётся DCI:** В канале **PDCCH**, который занимает первые 2 OFDM-символа в каждом субкадре (параметр CFI=2 в текущей реализации, а вообще бывает от 1 до 3)
2. **Как делятся ресурсы:** Область управления делится на блоки **CCE** (Control Channel Element). Один CCE=36 ресурсных элементов (RE), или 36 * 2 = 72 бита после QPSK(quadrature phase shift keying)
3. **Уровень агрегации (AL):** Одно DCI сообщение может занимать 1, 2, 4 или 8 блоков CCE:
   - AL = 1 (72 бита) - для хорошего канала возле вышки.
   - AL = 8 (576 бит) - для плохого канала на краю соты. Полезных бит всё те же 27, но за счёт избыточности надёжность вырастает
4. **Адресация:** Телефон узнаёт, что DCI предназначен именно ему, с помощью контрольной суммы CRC (cyclic redundancy check), маскированной его личным номером **C-RNTI**.

### Код скрипта

Скрипт проверяет сквозную цепочку без шума(пока что):

```matlab
% параметры соты 10 МГц
enb.NDLRB = 50; enb.CyclicPrefix = 'Normal'; enb.CFI = 2;
enb.CellRefP = 1; enb.NCellID = 0; enb.NSubframe = 0;

% DCI generation
ueRNTI = 100;
[~, dciBits] = lteDCI(enb, struct('DCIFormat', 'Format1A'));

% AL = 4 (4*72 = 288 bit)
AL = 4;
codedBits = lteDCIEncode(enb, dciBits, ueRNTI, AL*72);

% subframe malloc + filling
pdcchIndices = ltePDCCHIndices(enb);
allBits = -1 * ones(length(pdcchIndices) * 2, 1);
allBits(1:AL*72) = codedBits;

subframeGrid = lteDLResourceGrid(enb);
subframeGrid(pdcchIndices) = ltePDCCH(enb, allBits);

% decode
rxSymbols = subframeGrid(pdcchIndices);
rxLLR = ltePDCCHDecode(enb, rxSymbols);
[rxDciBits, rxRNTI] = lteDCIDecode(enb, rxLLR(1:AL*72), length(dciBits), 'Format1A');
```
