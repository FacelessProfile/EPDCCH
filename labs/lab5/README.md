# Лабораторная работа 5 (Практика 2): Сверточный код и декодер Витерби

## Как это понимать с нуля
В реальном радиоэфире из-за шумов биты портятся: вместо 0 прилетает 1, или наоборот. Если передать биты напрямую, текст превратится в кашу из опечаток.

Чтобы этого не происходило, мы добавляем в сообщение умную избыточность:
1. **Сверточный кодер** связывает каждый информационный бит с предыдущими через память и выдает по 2 бита в канал на каждый входящий бит.
2. Даже если несколько бит в канале перевернутся шумом, **декодер Витерби** найдет наиболее правдоподобный путь по графу состояний и на 100% восстановит исходные биты.

---

## Вариант 8 и параметры кодера
* Скорость кодирования: $R = 1/2$ (на выходе кодера в 2 раза больше бит: $270 \to 540$).
* Длина кодового ограничения: $K = 7$ (память на 6 триггеров задержки).
* Восьмеричные полиномы:
  * $171_8 = 1111001_2 \implies X = x \oplus D_1 \oplus D_2 \oplus D_3 \oplus D_6$
  * $133_8 = 1011011_2 \implies Y = x \oplus D_2 \oplus D_3 \oplus D_5 \oplus D_6$

## Разбор кода: как работают кодер и декодер

### 1. Сверточный кодер (`encode_conv`)
Кодер устроен как регистр сдвига на 6 бит:
```matlab
function encoded = encode_conv(bits)
    mem = zeros(1, 6);
    encoded = zeros(1, 2 * length(bits));
    
    for i = 1:length(bits)
        x = bits(i);
        encoded(2*i-1) = mod(x + mem(1) + mem(2) + mem(3) + mem(6), 2);
        encoded(2*i)   = mod(x + mem(2) + mem(3) + mem(5) + mem(6), 2);
        
        mem = [x, mem(1:5)];
    end
end
```
* В цикле берется один бит $x$.
* Первый выходной бит формируется суммой по модулю 2 текущего бита и ячеек 1, 2, 3, 6 (полином 171).
* Второй выходной бит формируется суммой по модулю 2 текущего бита и ячеек 2, 3, 5, 6 (полином 133).
* Регистр памяти сдвигается: новый бит встает на место `mem(1)`, остальные сдвигаются вправо, а самый старый выпадает.

### 2. Моделирование ошибок в канале
Мы намеренно инвертируем 6 бит в разных местах закодированного вектора, чтобы проверить исправляющую способность:
```matlab
error_indices = [15, 64, 150, 280, 395, 510];
rx_coded(error_indices) = ~rx_coded(error_indices);
```

### 3. Декодер Витерби (`decode_viterbi`)
Декодер хранит состояние регистра памяти. 6 бит памяти дают $2^6 = 64$ возможных состояния:
```matlab
weights = [32; 16; 8; 4; 2; 1];
states = mod(floor((0:63)' ./ [32 16 8 4 2 1]), 2);
num_steps = length(rx_bits) / 2;
path_metric = [0; inf(63, 1)];
history = cell(64, 1);
```
* В начале мы знаем, что регистр кодера был обнулен: начальное состояние $S_1 = [0,0,0,0,0,0]$ имеет метрику 0, а все остальные 63 состояния — бесконечность (`inf`).
* На каждом шаге $t$ приходит пара искаженных бит `rx_pair`:
  1. Для каждого активного состояния перебираются два варианта: что было передано — 0 или 1?
  2. Вычисляются идеальные биты `ideal_y1` и `ideal_y2`.
  3. Считается штраф: сколько бит не совпало с принятыми (0, 1 или 2).
  4. Считается суммарная стоимость пути `total_cost = path_metric(s) + penalty`.
  5. **Правило ACS (Add-Compare-Select):** если в следующее состояние `next_s` приходит путь лучше, чем был раньше, мы перезаписываем его метрику и сохраняем новую историю бит. Худший путь навсегда выбрасывается.
* В конце сообщения ищется состояние с минимальной суммарной метрикой: `[~, best_state] = min(path_metric)`. История этого состояния `history{best_state}` и есть исходные биты.

### Результат
Скрипт полностью восстанавливает исходный текст:

```text
Принятый текст:   "This is a test message for practice 2 var 8.."

```
